# Require passkey (app lock)

Settings → Security → **Require passkey**. The app asks for Face ID, Touch ID or the device's own screen lock (a WebAuthn platform passkey, `userVerification: required`) before it shows anything. It is for a phone or a Mac that is handed to someone while unlocked.

- **Per device.** Each device makes its own passkey and keeps its own timeout, in `localStorage` with the other settings (`settings.lock`). Nothing goes to Pocket's server: there are no accounts there, so there is nothing to check against, and no migration or deploy order to think of.
- **Lock after** counts from the last interaction (touch, key, scroll): Immediately, 1, 5, 15 minutes, 1 or 4 hours. The time of the last interaction is kept in `localStorage` (`pocket.lock.active`) every few seconds and when the app leaves the screen, so the same rule decides a relaunch and a return from the background. "Immediately" locks as soon as the app leaves the screen; an open app untouched for a minute locks in any case. A touch after the time has run out locks; it never extends it.
- **Locked** looks like the app unlocked, so little changes on the screen: the page is shown as it is, **with its amounts hidden** (below), and a bar with one **Unlock** button sits over the navigation bar (the tab bar on a phone, the sidebar on a wide screen). Nothing behind the bar can be touched (`inert`). The names, descriptions and charts stay visible. A sheet that was open (a half-written transaction) is hidden while locked and comes back after unlocking.
- **App switcher.** With the lock on, the page is hidden (`html.shielded`) the moment the app leaves the screen, so iOS's picture of it shows the background, not balances.
- **Hide amounts** (Settings → Appearance) hides amounts everywhere in the app, not only on Home, and the lock turns it on while locked. Two layers: every amount goes through `money()` and `shares()` in `lib/format.js`, which turn the digits into dots (`€1,234.50` becomes `€•,•••.••`, so the layout stays), and `html.amounts-hidden` blurs every element marked `class="blurable"` (`styles.css`), so the dots are blurred too. Anything new that shows an amount must use `money()`/`shares()` and put `blurable` on the element (or on a `<span>` around the amount inside a sentence). What you type into a form is not hidden.
- **First load.** The service worker (`sw.js`) serves the app shell as `<html data-amounts-pending class="amounts-hidden">`, so the page always starts with its amounts hidden, whether or not the lock is on. `initLock()` clears the flag (`lock.pending`) once it has decided if the app is locked; if it is, it stays hidden, if not the amounts appear. This keeps balances from flashing when the Home Screen app comes back. Without a service worker (first visit, dev server) the page opens as before.
- **On a wide screen** the sidebar shows through the Unlock bar, heavily blurred.
- **Unlock** is the button on the lock screen. **Ask automatically** (on by default, Settings → Security) also opens the Face ID or Touch ID prompt by itself, once, when the lock screen comes up and when the app comes back to the screen (never while it is hidden). If the browser refuses a prompt that did not come from a tap, or it is cancelled, nothing is shown and the Unlock button is what is left: there is no retry loop. Some Safari versions may want the tap, and the Home Screen app has had reports of doubled or stalled prompts on launch; switch the setting off if that happens.
- **Turning it off** needs the passkey too, and so does **showing amounts again** (the eye on Home, the Hide amounts switch in Settings) while the lock is on and they are hidden. Hiding never asks.
- **Lost passkey** (new phone, iCloud Keychain reset): remove the app from the Home Screen, or clear the site's data, and open it again. That clears the Firefly token too, so paste it again.

What it does not do:
- It is a lock on what the app shows. The Firefly token and the cache stay in the browser (`localStorage`, IndexedDB), so it does not stop someone with the browser's developer tools. Encrypting the token with the WebAuthn PRF extension would, but PRF support is uneven across Safari and Chrome.
- Face ID or Touch ID falls back to the device passcode or password.
- Push notifications show their text on the lock screen regardless.
